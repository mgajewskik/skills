# Drift

For desired state (source) and live state disagreeing. The deliverable is a per-field decision about which side wins, carried out as source changes, reversible live changes logged via `plan` and `run --from-plan`, or user-executed handoffs, and a re-check showing the drift gone without new drift. Reverting live state to source is a live change and can undo a deliberate emergency fix.

1. **Scope the comparison.** Source revision, target, and the bounded set of fields compared, with the tool and version that produced the comparison. Read what the comparison tool writes: some refresh operations update stored state. Save the drift list as an artifact. Done when the drift list is reproducible by rerunning one read-only command.
2. **Find every writer.** For each drifted field: declared owner, reconcilers, automation, and recent human changes, including your own earlier changes. Name which writer wins the next reconcile (**[verify-the-negative-space](../principles/verify-the-negative-space.md)**). Done when every drifted field has its writers and winning reconciler named.
3. **Classify each difference.** Undocumented live fix, platform default or server-side mutation, out-of-band manual change, partial or failed earlier apply, or an upstream provider change. Log evidence for each; unknown stays unknown. Done when every drifted field has a logged classification or is marked unknown.
4. **Decide direction with the user.** Adopt into source, revert live to source, transfer ownership, or ignore a field the source should never have managed. The user chooses per field; you recommend with the evidence. Done when each drifted field has a user-confirmed direction logged as a decision.
5. **Carry it out.** Adopt-into-source goes through Implement. Revert-live goes through Deploy when reconciling via the normal source rollout path, or through Live modify for direct field patches (following `work/SKILL.md` authority, reversibility, and grants). Any removal goes through Teardown. Return to step 6 once changes land. Done when every decided field's change is executed and logged, or handed over.
6. **Re-check.** Rerun the step 1 comparison: decided fields show no difference, no new fields drifted, consumers unaffected. Log the result as evidence. Done when the rerun comparison and consumer checks are `established` in the log.

**Reply.** Drift found (fields and classification), decision and owner per field, what was changed or handed over, and the re-check result.
