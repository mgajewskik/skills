# Debug

The deliverable is a cause established by evidence, or the named evidence gap that blocks it, plus remediation options. Nothing changes on the target during this playbook. Diagnosis never silently becomes repair.

1. **Fix the contract.** Environment, exact target, symptom, observation window, caller, and mode (execute read-only probes, or suggest-only). Ask whether consumers are affected right now; active impact goes to Incident first, because containment comes before cause. Name the identity the probes run as; when it is broader than read-only, ask the user for a read-only one (**[infra-act-through-the-narrowest-identity](../principles/infra-act-through-the-narrowest-identity/SKILL.md)**). Ask only for facts that change the next safe probe. Done when you could write the target into a command without guessing; until then emit no command.
2. **Read before probing.** Open the relevant source, its overrides, and the installed versions of every tool whose behavior matters (locks, manifests, `--help`, versioned docs). Look in the target's repository for an existing runbook, playbook, or the one an alert links to, and follow its investigation steps under this contract. Done when each nontrivial tool behavior you rely on has a version-matched source (**[ground-claims-in-the-environment](../principles/ground-claims-in-the-environment/SKILL.md)**) and any existing runbook has been read.
3. **Make the symptom red.** Write one binary check that fails now: the consumer's failing request, the saved error, the wrong effective value. Add an anti-criterion that catches a false diagnosis, such as blaming a valid source file without loaded-state evidence. Prefer existing evidence; never recreate an incident with traffic or writes beyond scope. Done when the check is red on evidence bound to target and time and logged as evidence, or you have logged why it cannot be reproduced.
4. **Trace the state chain.** Start with what changed in and just before the window: deploys, configuration and flag changes, IaC applies, your own earlier changes, certificate and credential expiry, shifts in load. Then source intent, effective input after overrides, loaded state, consumer outcome. Log each link as evidence (established, failed, or unverified), and never join two observations from different hosts, revisions, identities, or windows into one chain. Done when the first divergent link is identified or the unverified links are listed.
5. **Loop one probe at a time.** Rank a leading hypothesis and a real alternative, each with the signal it predicts and the result that would weaken it. Pick the narrowest read-only observation that separates them, show the exact command, run and log it (or log it as a plan for the user in suggest-only mode and wait; a new message without the result is context, not permission to advance), interpret it, re-rank. An unexpected result can mean the observation method is wrong; rule that out before blaming the system. Opening a database, mounting a volume, or starting a process can write even when meant as a read; use a read-only mode or a copy kept within the target's environment (**[infra-leave-no-residue](../principles/infra-leave-no-residue/SKILL.md)**), and treat a probe that still writes as beyond this playbook's authority. A probe that repeats retries only transient errors, backs off, and has a cap. Two failed remedies sharing a premise send you to **[attack-the-premise](../principles/attack-the-premise/SKILL.md)**. Done when the mechanism is established, the remaining causes cannot be separated safely, or the next probe exceeds authority.
6. **Conclude.** Observed facts with evidence pointers; inferred mechanism (**[fix-root-causes](../principles/fix-root-causes/SKILL.md)**) with confidence and the competitors not excluded; unknowns and what would settle them. Offer remediation options with tradeoffs, impact, reversibility class, and recovery limits, named as mechanisms without executable commands until the user picks one. Log the mechanism as the root cause with its confidence, and each option as a note.
7. **Route.** A user-chosen fix to source goes to Change; a direct live fix goes to Live modify; active impact goes to Incident. Routing grants no new authority.

**Reply.** Leading hypothesis, evidence so far, what is excluded, risk class, and one status: `awaiting probe result`, `awaiting user choice`, or `diagnosis complete`.
