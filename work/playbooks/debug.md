# Debug

The deliverable is a cause established by evidence, or the named evidence gap that blocks it, plus remediation options. Nothing changes on the target during this playbook. Diagnosis never silently becomes repair.

1. **Fix the contract.** Environment, exact target, symptom, observation window, caller, and mode (execute read-only probes, or suggest-only). Ask whether consumers are affected right now; active impact goes to Incident first, because containment comes before cause. Name the identity the probes run as; when it is broader than read-only, ask the user for a read-only one (**[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity.md)**). Ask only for facts that change the next safe probe. Done when you could write the target into a command without guessing; until then emit no command.
2. **Read before probing.** Open the relevant source, its overrides, and the installed versions of every tool whose behavior matters (locks, manifests, `--help`, versioned docs). Look in the target's repository for an existing runbook, playbook, or the one an alert links to, and follow its investigation steps under this contract. Done when each nontrivial tool behavior you rely on has a version-matched source (**[ground-claims-in-the-environment](../principles/ground-claims-in-the-environment.md)**) and any existing runbook has been read.
3. **Make the symptom red.** Write one binary check that fails now: the consumer's failing request, the saved error, the wrong effective value. Add an anti-criterion that catches a false diagnosis, such as blaming a valid source file without loaded-state evidence. Prefer existing evidence; never recreate an incident with traffic or writes beyond scope. Save non-trivial raw failing outputs (responses, error windows, configs) locally via `--artifact` or piped `--artifact-name` so they can be revisited offline without re-querying live systems. Done when the check is red on evidence bound to target and time and logged as evidence, or you have logged why it cannot be reproduced.
4. **Trace the state chain.** Start with what changed in and just before the window: deploys, configuration and flag changes, IaC applies, your own earlier changes, certificate and credential expiry, shifts in load. Then source intent, effective input after overrides, loaded state, consumer outcome. Log each link as evidence (`established`, `failed`, or `unverified`), attaching non-trivial raw probe outputs (effective configs, loaded state, pod/service descriptions, traces) via `--artifact` or `--artifact-name`, and keeping every observation bound to the same host, revision, identity, and window before joining links into one chain. Done when the first divergent link is identified or the unverified links are listed.
5. **Loop one probe at a time.** Rank a leading hypothesis and a real alternative, each with the signal it predicts and the result that would weaken it. Pick the narrowest read-only observation that separates them, show the exact command, run and log it with `run --class read-only` (capturing non-trivial raw output locally via `--artifact` or piped `--artifact-name`), or in suggest-only mode log `plan --by user --class read-only` and wait (a new message without the result is context, not permission to advance; once the user pastes back the command and output, confirm it matches the handed-over plan and close it with `run --from-plan <n> --by user --outcome ok|failed|unknown --result ...`, saving non-trivial pasted output via `--artifact` or `--artifact-name`), interpret it, re-rank. An unexpected result can mean the observation method is wrong; rule that out before blaming the system. Opening a database, mounting a volume, or starting a process can write even when meant as a read; use a read-only mode or a copy kept within the target's environment (**[leave-no-residue](../principles/leave-no-residue.md)**), and treat a probe that still writes as beyond this playbook's authority. A probe that repeats retries only transient errors, backs off, and has a cap. Two failed remedies sharing a premise send you to **[attack-the-premise](../principles/attack-the-premise.md)**. Done when the mechanism is established, the remaining causes cannot be separated safely, or the next probe exceeds authority.
6. **Conclude.** Observed facts with evidence pointers; inferred mechanism (**[fix-root-causes](../principles/fix-root-causes.md)**) with confidence (`established`, `leading-hypothesis`, or `unknown`) and the competitors not excluded; unknowns and what would settle them. Offer remediation options with tradeoffs, impact, reversibility class, and recovery limits, named as mechanisms without executable commands until the user picks one. Log the mechanism via `root-cause`, and each option as a note. Done when `root-cause` and remediation options are logged.
7. **Route.** A user-chosen fix to source goes to Fix; a direct live fix goes to Live modify; active impact goes to Incident; a follow-up code audit goes to Investigate. Routing grants no new authority. Done when the diagnosis is delivered or the switch to the user-chosen playbook is logged.

**Reply.** Leading hypothesis, evidence so far, what is excluded, risk class, and one status: `awaiting probe result`, `awaiting user choice`, or `diagnosis complete`.
