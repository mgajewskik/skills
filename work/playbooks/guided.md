# Guided

For when the user runs every command and makes every change, and you guide. Guided wraps the playbook the task matches (Debug, Live modify, Deploy, and the rest): copy that playbook's steps as usual and carry them out through the handover loop below. The deliverable is the wrapped playbook's deliverable, reached through commands the user ran and output the user pasted back, with a log the user can follow or resume alone. You read local source, run offline local checks that reach no remote system (renders, `validate`, unit tests), and write only the work log and its staging files under `/tmp`; you execute nothing against live systems and edit nothing else, whatever the class or environment.

1. **Fix the contract.** The wrapped playbook, environment, target, and the shell the user runs from. Start the log with `--playbook "<wrapped>, guided"`. The first handover is a read-only check of where the user's commands will land: current context, account, or host, the identity they run as (**[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity/SKILL.md)**), and the `--version` of each tool you will rely on (**[ground-claims-in-the-environment](../principles/ground-claims-in-the-environment/SKILL.md)**). Done when that output is pasted back and matches the target.
2. **Hand over one step.** Give the exact command as a copyable block with what it does and why now, its class, the target it hits, the signal you expect, and what to paste back. Independent read-only commands may go together; a change goes alone. Shape commands for pasting: a bounded time window, line count, and field selection, never a full secret or log dump (**[leave-no-residue](../principles/leave-no-residue/SKILL.md)**). Log each command as a plan for the user, a change with its revert; a revert you hand over is logged once the user reports running it, as their run with `--reverts`. Done when the command is logged and handed over.
3. **Order every change.** Snapshot command first; its pasted output becomes the change's revert artifact. Then the preview or dry run when the tool offers one, then the change with its revert command beside it, then the verification command (**[design-recovery-first](../principles/design-recovery-first/SKILL.md)**, **[prove-it-works](../principles/prove-it-works/SKILL.md)**). The wrapped playbook's classification stands: name an irreversible step as irreversible and state what cannot come back before handing it over. Done when the snapshot output is logged before the change is handed over.
4. **Read what comes back.** Ask for the command line together with its output, and check it matches what you handed over (target, flags, identity) before trusting it; a mismatch is a finding, not evidence: log what the user actually ran as their own run (a change with its revert), note the mismatch, and leave the plan open. Log a match as the user's run from that plan with a one-line result, save long output to a file and attach it as an artifact, and log each claim it supports or fails as evidence. A message without the requested output is context, not permission to advance. When the log refuses pasted output as a secret, save a redacted copy, delete the unredacted file, and name the line so the user can judge whether to rotate it.
5. **Re-rank and continue** the wrapped playbook from what the output showed, one handover at a time. Two failed remedies sharing a premise send you to **[attack-the-premise](../principles/attack-the-premise/SKILL.md)**.
6. **Close.** Close the log with the wrapped playbook's outcome. The summary names what the user changed and the revert-plan entries still live.

**Reply.** Each turn: the wrapped playbook's current step, what the last output established, and the next command block with what to paste back. At close: the wrapped playbook's reply and the log path.
