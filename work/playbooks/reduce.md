# Reduce

For making code, tests, scripts, or configuration smaller and simpler: cleanup, deleting what is no longer needed, collapsing slop that was once needed. The deliverable is the smallest end state that keeps the **contract**, verified by the same checks before and after. Judge what the code looks like *after*, not the size of the diff: writing 50 lines that delete 200 is a win, and avoiding churn is not a goal. "No worthwhile reduction found" is a valid result.

1. **Scope.** Honor the named file, subsystem, diff, or proposal. With no target, run a bounded hot-spot scan (recent churn, large or duplicated modules, stacked config layers) and pick from what it finds. Done when the scope is a list of paths.
2. **Fix the contract.** By default it is current observable behavior: inputs, outputs, errors, ordering, invariants, side effects, public interfaces and schemas, effective configuration, and the performance, security, and concurrency properties consumers rely on. When the user presents a target behavior, the target is the contract, and removals it names are confirmed. Code no consumer can reach is not behavior and goes without asking. Behavior outside the target that still has consumers (callers, tests, public keys, documented promises, ADRs), and behavior you only suspect is unused, goes on a removal list the user confirms before it goes. Log the contract and the list as notes. Done when every surviving behavior and every removal candidate is named.
3. **Pin a baseline.** Record the working tree's existing uncommitted edits so your cuts stay distinguishable from them. Run the smallest existing check that proves the contract: targeted tests, a build, schema validation, rendered or effective config saved as an artifact, or a deterministic probe. Where coverage is missing and a cut is risky, add a characterization test at the interface first (**[test-behavior-not-implementation](../principles/test-behavior-not-implementation/SKILL.md)**). Done when the baseline is green and logged as evidence; a risky cut without a credible baseline stops here.
4. **Find the cuts.** Ask of the scope: what is the smallest code that meets the contract (two functions instead of fourteen, or none)? What need does each piece serve, and is it still live? What becomes obsolete once it goes? Look for:
   - code no caller reaches, flags fixed to one value, compatibility paths with no remaining consumer, and the tests, config, and docs that served only them;
   - the same behavior or decision in several places (**[laziness-protocol](../principles/laziness-protocol/SKILL.md)**);
   - pass-through layers, one-caller wrappers, and adapters with one implementation (**[minimize-reader-load](../principles/minimize-reader-load/SKILL.md)**). Apply the deletion test: if removing a module makes complexity vanish, it was pass-through; if complexity spreads into its callers, it earns its place;
   - custom types and classes that only carry data a map, record, or list would hold;
   - config layers, overrides, and defaults that restate the effective value.

   Choose simple (one concept, not intertwined with others) over easy (familiar). An argument for keeping code ("keep what exists", "flexibility", "separation of concerns", "type safety", "readability") names the observed need and the concepts it costs; otherwise the code goes. Keep a PAGNI: an evidence-based need whose retrofit costs ten times more than keeping it, and keeping it is cheap. Always keep security fundamentals, audit trails, data you cannot recover, compliance obligations, framework conventions, and the public compatibility the contract names. Done when each cut has evidence (zero references, one caller, identical rendered output) and the contract check that guards it.
5. **Cut in verifiable units.** One coherent reduction per unit, removing everything it makes obsolete (callers, tests, config, docs), then rerun the baseline before the next (**[subtract-before-you-add](../principles/subtract-before-you-add/SKILL.md)**, **[sequence-verifiable-units](../principles/sequence-verifiable-units/SKILL.md)**). Move callers and delete the old path in the same unit (**[migrate-callers-then-delete-legacy-apis](../principles/migrate-callers-then-delete-legacy-apis/SKILL.md)**); a sweep across many sites gets a codemod or script (**[build-the-lever](../principles/build-the-lever/SKILL.md)**). Delete tests of a removed shallow layer once interface-level tests cover the same behavior. Merge config only when a validator, schema, or rendered-output comparison proves the effective values equal. Live resources leave through Teardown; a contract change with independently deployed consumers goes through Migration.
6. **Measure the end state.** Before and after on the axes that moved: hand-authored lines (source, config, tests), files, concepts and custom types, public interfaces, layers a reader traces, dependencies. The total must shrink; an axis that grew names the larger reduction it bought. Reduction means fewer things to understand: reformatting, minifying, joined lines, generated, vendored, or lockfile changes, removed safeguards or meaningful comments, and dropped tests of surviving behavior all score zero.
7. **Prove it.** Rerun the exact baseline and read the whole diff against the contract (**[prove-it-works](../principles/prove-it-works/SKILL.md)**). Done when the baseline is green, each confirmed removal is gone, and nothing outside the removal list changed behavior.

**Reply.** The contract kept, removals made and who confirmed each, the removal list still awaiting confirmation, before and after measurements, checks run, and what remains unproven.
