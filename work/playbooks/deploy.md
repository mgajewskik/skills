# Deploy

The deliverable is a rollout executed unit by unit, each unit accepted on evidence before the next. Follow the Authority, reversibility, and grants rules in `work/SKILL.md`: reversible non-production units (or production units inside a logged session grant) are executed by the agent from their logged `plan --by agent` and recorded with `run --from-plan`; production units outside a grant and every irreversible step are handed over as `plan --by user`. The agent never retries on its own.

1. **Pin the artifact and target.** Exact artifact revision or digest, environment, target set resolved to identifiers, the identity each unit runs as (**[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity.md)**), who executes each unit, and installed tool versions (**[ground-claims-in-the-environment](../principles/ground-claims-in-the-environment.md)**). Identify drift, partial earlier runs, and every other writer of the same fields. Done when the target set came from a read-only query, not from memory.
2. **Take the baseline.** Current consumer behavior, effective and loaded state, and the negative-space neighbours, each bound to identity, location, and time and logged as evidence. Done when the acceptance checks would go red if the rollout did nothing.
3. **Fix the predicate before execution.** Acceptance criteria and anti-criteria at the consumer, observation window, population, and stop thresholds chosen from this workload. Log them as a note for each unit. Never relax them after the first unit. Done when each unit's predicate, window, and stop thresholds are logged.
4. **Preview with the closest real engine.** Produce the plan, diff, or dry run the unit will execute against, save it as an artifact, and note what it cannot see. Replacements and deletions in a preview get named one by one; any deletion routes that part through Teardown. Done when the preview artifact is saved and every replacement or deletion is accounted for.
5. **Cut units, classify, and log plans.** Smallest representative unit first, per **[bound-change-exposure](../principles/bound-change-exposure.md)** and **[sequence-verifiable-units](../principles/sequence-verifiable-units.md)**. For each unit, answer what a repeat does and what an interruption leaves behind (**[make-operations-idempotent](../principles/make-operations-idempotent.md)**), name what recovery restores and cannot (**[design-recovery-first](../principles/design-recovery-first.md)**), and classify reversibility under `work/SKILL.md`. Mixed versions or persisted formats route through Migration. Capture each unit's prior snapshot artifact where safe, and log each unit's exact command, target, identity, and revert (or `--no-revert`) as `plan --by agent` or `plan --by user`. Done when every unit has a logged `plan` entry with verified recovery limits.
6. **Get an independent verdict on the prepared rollout.** Always gated before live execution regardless of diff size: run a fresh, non-author read-only subagent following [`review.md`](review.md) (`Mode: full`) on the artifact revision, preview, unit classification, logged plans and `revert` view, criteria, anti-criteria, and work log — never your conclusion. Fix every `BLOCKER` (superseding any changed plan) and re-review in `Mode: delta` (or `Mode: full` if scope widened) until `Decision: PASS` (or an explicit user waiver), capped at 2 follow-up rounds before escalating; any substantive edit after `PASS` triggers `Mode: delta`. When running inside any subagent spawned by a parent orchestrator (such as an `Auto` unit), never spawn a reviewer subagent yourself; stop here before step 7 and hand back these review brief inputs and your delegate log id so the main orchestrator spawns the fresh reviewer subagent directly and then dispatches steps 7–9 continuing the same reviewed delegate log once `Decision: PASS` is reached. Done on `Decision: PASS` bound to the artifact revision (or handoff to the main orchestrator).
7. **Run one unit (repeat steps 7–9 per unit).** When continuing from a delegated preparation phase reviewed by the main orchestrator, reuse that same reviewed delegate log id (never `new --parent`) so `run --from-plan` resolves step 5's logged plans. Resolve the target and identity again and compare them with step 1; if live state drifted from the step 5 snapshot or plan, capture a fresh snapshot, supersede the plan, and re-run step 6 review before executing (inside a delegated subagent, stop before executing and hand back to the main orchestrator to trigger fresh `review.md` `Decision: PASS`). For an agent-run unit: execute the exact step 5 `plan --by agent` command, then log `run --from-plan <n> --outcome ok|failed|unknown --result ...`. For a handed-over unit: present the exact step 5 `plan --by user` command, target, and expected signal for the user to execute. Done when the unit's execution outcome is logged or the exact plan is handed over.
8. **Verify the unit.** For a handed-over unit, first confirm the user ran the exact command handed over and log `run --from-plan <n> --by user --outcome ok|failed|unknown --result ...`. Then observe effective state, loaded state, consumer outcome (**[prove-it-works](../principles/prove-it-works.md)**), and negative space (**[verify-the-negative-space](../principles/verify-the-negative-space.md)**) with bounded read-only probes bound to the running revision. Polling for convergence backs off and has a cap. Log each rollout claim as evidence with `--revision <artifact revision>`. Keep rollout acceptance separate from overall application health: record any unrelated existing fault as a `note` (not failed rollout evidence) — it does not fail the rollout, and an accepted rollout does not make the application healthy. Done when every required acceptance and negative-space claim for this unit is logged as evidence.
9. **Gate.** Advance to the next unit only when `check <id> --since <the unit's run entry> --max-age-hours <the unit's observation window> --revision <artifact revision> --require <claim> ...` (one `--require` per acceptance and negative-space claim from step 3) exits 0: every required and recorded claim established on fresh evidence for that revision, with no later failed or unverified one. On a stop signal for a unit you executed: run its revert from `revert-plan`, log it with `--reverts <n> --outcome ok|failed|unknown`, and halt (route to `Incident` immediately if consumer impact remains active after a failed or unknown revert). Any stop signal, drift, ownership conflict, or unexplained partial result halts expansion and goes back to the user with evidence; a timeout or partial run gets an inventory of what completed before anyone proposes a repeat (**[bound-change-exposure](../principles/bound-change-exposure.md)**). Promote only the contiguous run of accepted units. Before calling the rollout done, walk the residue list (**[leave-no-residue](../principles/leave-no-residue.md)**). Done when all planned units pass `check` and residue is cleared, or the rollout halts cleanly with evidence.

| State | Required evidence |
| --- | --- |
| `prepared` | Artifact revision, preview, unit classification, step 5 logged `plan` entries (with reverts/snapshots), criteria, anti-criteria, recovery limits, `Decision: PASS` review verdict. |
| `approved` | Handed-over unit: user's approval of that exact logged `plan --by user`. Agent-run unit: `Decision: PASS` plus confirmed step 7 pre-execution target and identity match. |
| `executed` | The logged `run --from-plan` outcome (`ok`), or the user's verified execution logged as `run --from-plan --by user`. Acceptance still unverified. |
| `accepted` | Every required acceptance and negative-space claim `established` for the current revision via `check --since <run entry>`. |
| `failed` / `halted` / `reverted` | A required result failed, a forbidden result occurred, or a stop condition fired; `reverted` once the revert is verified with `--outcome ok`. |
| `unverified` | Evidence missing, stale, from another revision or context, or not covering the claim. |

**Reply.** Artifact revision, units with their states and who executed each, evidence per claim, review verdict, and the one next action with the minimal result to send back.
