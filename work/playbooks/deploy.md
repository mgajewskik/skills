# Deploy

The deliverable is a rollout executed unit by unit, each unit accepted on evidence before the next. A non-production unit that passes the reversibility check is executed by the agent, logged with its revert first. Production units outside a grant, and every irreversible step, are handed to the user to execute. The agent never retries on its own.

1. **Pin the artifact and target.** Exact artifact revision or digest, environment, target set resolved to identifiers, the identity each unit runs as (**[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity/SKILL.md)**), who executes each unit, and installed tool versions (**[ground-claims-in-the-environment](../principles/ground-claims-in-the-environment/SKILL.md)**). Identify drift, partial earlier runs, and every other writer of the same fields. Done when the target set came from a read-only query, not from memory.
2. **Take the baseline.** Current consumer behavior, effective and loaded state, and the negative-space neighbours, each bound to identity, location, and time and logged as evidence. Done when the acceptance checks would go red if the rollout did nothing.
3. **Fix the predicate before execution.** Acceptance criteria and anti-criteria at the consumer, observation window, population, and stop thresholds chosen from this workload. Log them as a note for each unit. Never relax them after the first unit.
4. **Preview with the closest real engine.** Produce the plan, diff, or dry run the unit will execute against, save it as an artifact, and note what it cannot see. Replacements and deletions in a preview get named one by one; any deletion routes that part through Teardown.
5. **Cut units and classify each.** Smallest representative unit first, per **[bound-change-exposure](../principles/bound-change-exposure/SKILL.md)** and **[sequence-verifiable-units](../principles/sequence-verifiable-units/SKILL.md)**. For each, answer what a repeat does and what an interruption leaves behind (**[make-operations-idempotent](../principles/make-operations-idempotent/SKILL.md)**), and what recovery restores and cannot (**[design-recovery-first](../principles/design-recovery-first/SKILL.md)**). Then check reversibility per unit: snapshot, revert command, nothing lost or sent, verification both ways. Mixed versions or persisted formats route through Migration.
6. **Get an independent verdict on the prepared rollout.** A non-author reviewer checks the artifact, preview, unit classification, logged plans and handoffs, and criteria. Done on `Decision: PASS` bound to the artifact revision; an edit after the verdict voids it.
7. **Run one unit.** Resolve the target and identity again and compare them with step 1. Reversible, and outside production or inside a grant: save the snapshot as an artifact, log the run with its revert, execute exactly that command, and log its outcome as evidence. Otherwise: log the exact command, its target, and the expected signal as a plan for the user; the user executes.
8. **Verify the unit.** For a handed-over unit, first confirm the user ran exactly the command handed over. Then observe effective state, loaded state, consumer outcome (**[prove-it-works](../principles/prove-it-works/SKILL.md)**), and negative space (**[verify-the-negative-space](../principles/verify-the-negative-space/SKILL.md)**) with bounded read-only probes bound to the running revision. Polling for convergence backs off and has a cap. Log each claim as evidence with that revision. Keep rollout acceptance separate from overall application health: an unrelated existing fault does not fail the rollout, and an accepted rollout does not make the application healthy.
9. **Gate.** Advance only when `check <id> --since <the unit's run or plan entry> --max-age-hours <the unit's observation window>` exits 0: every claim of the unit established on fresh evidence, with no later failed or unverified one. A stop signal on a unit you executed: run its revert from `revert-plan`, log it with `--reverts`, and halt. Any stop signal, drift, ownership conflict, or unexplained partial result halts expansion and goes back to the user with evidence; a timeout or partial run gets an inventory of what completed before anyone proposes a repeat (**[bound-change-exposure](../principles/bound-change-exposure/SKILL.md)**). Promote only the contiguous run of accepted units. Before calling the rollout done, walk the residue list (**[leave-no-residue](../principles/leave-no-residue/SKILL.md)**).

| State | Required evidence |
| --- | --- |
| `prepared` | Artifact, preview, unit classification, logged plans or handoffs, criteria, recovery limits, review verdict. |
| `approved` | Handed-over unit: the user's approval of that exact command. Agent-run unit: its run logged with the revert. |
| `executed` | The logged outcome, or the user's execution report. Acceptance still unverified. |
| `accepted` | Every acceptance and negative-space claim `established` for the current revision. |
| `failed` / `halted` / `reverted` | A required result failed, a forbidden result occurred, or a stop condition fired; `reverted` once the revert is verified. |
| `unverified` | Evidence missing, stale, from another context, or not covering the claim. |

**Reply.** Artifact revision, units with their states and who executed each, evidence per claim, review verdict, and the one next action with the minimal result to send back.
