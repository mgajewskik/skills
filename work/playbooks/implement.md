# Implement

The deliverable is a local, reviewed, verified change to code (application code, tests, scripts, config, or infrastructure as code), ready to ship. Only the files the user asked about change.

1. **Record the baseline.** Working tree status, pre-existing staged and unstaged edits, and the scoped files' current content. Name the files you own and preserve everything else. Done when you can tell your diff apart from anyone else's.
2. **Read the contract around the target.** Callers and producers, consumers, overrides, generated outputs, existing checks, and installed tool versions (**[ground-claims-in-the-environment](../principles/ground-claims-in-the-environment/SKILL.md)**). Read any validator, renderer, or hook before running it; a local checkout can still call remote backends, through whatever identity is active (**[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity/SKILL.md)**). Broad discovery goes to an exploration subagent that saves its notes to a file outside the repo, for later briefs to point at. Done when every check you plan to run is classified as local-only or as a read-only remote call.
3. **Write criteria and make them red.** Binary criteria and anti-criteria, including one that catches a misleading pass (schema-valid but semantically wrong) (**[test-behavior-not-implementation](../principles/test-behavior-not-implementation/SKILL.md)**). For a defect, reproduce it with a failing test, a saved fixture, or a deterministic local render first. Done when the check fails on the current code for the reason you expect.
4. **Name the shape.** The data shape, its allowed states, inputs and overrides; for infrastructure, also environment identity and resource ownership. Resolve each decision in one place (**[model-the-domain](../principles/model-the-domain/SKILL.md)**). Stateful resources declare their guards in source: deletion protection or `prevent_destroy`, retention, backups that a destroy of this stack cannot reach, and state in a locked shared backend (**[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity/SKILL.md)**, **[design-recovery-first](../principles/design-recovery-first/SKILL.md)**); report a missing guard as a finding. Retry logic you write retries only transient errors, with backoff, jitter, and a cap, at one layer. For a novel consequential design, compare two or three genuinely different sketches (**[exhaust-the-design-space](../principles/exhaust-the-design-space/SKILL.md)**); for a mechanical edit, follow the existing pattern.
5. **Split into workstreams.** Map the work as a **task graph**: the workstreams the spec or plan declares, plus any found in steps 2 to 4, and which blocks which. Shared types, schemas, and scaffold land first, before any stream starts (**[foundational-thinking](../principles/foundational-thinking/SKILL.md)**). With one stream, work inline. When two or more sit on the **frontier** (unblocked, with disjoint file scopes), run them as parallel implementer subagents in the background on the current branch and working tree (**[separate-before-serializing-shared-state](../principles/separate-before-serializing-shared-state/SKILL.md)**). A stream edits only its file scope, runs only checks scoped to those files, and hands back its changed paths and evidence for the parent to log; the parent keeps staging, commits, the work log, shared files (lockfiles, generated outputs), generators, and whole-suite checks. Brief each through context pointers to the spec, the plan, the discovery notes, and commits, plus its criteria, its file scope, and the stream rule above. Done when every stream has an owner and no two streams write the same file.
6. **Make the smallest correct change** (**[laziness-protocol](../principles/laziness-protocol/SKILL.md)**). Subtract what this change makes obsolete (**[subtract-before-you-add](../principles/subtract-before-you-add/SKILL.md)**); keep compatibility paths and operational comments whose consumers you have not inventoried (**[preserve-compatible-transitions](../principles/preserve-compatible-transitions/SKILL.md)**). For a refactor, pin the observable output first and require test results unchanged and rendered output byte-identical afterwards.
7. **Verify offline in units.** With parallel streams, the parent takes each finished stream in turn: checks its reported paths against its scope and against `git status` minus the step 1 baseline, logs its evidence, and dispatches what it unblocked; generators and whole-suite checks run once no stream is in flight (**[sequence-verifiable-units](../principles/sequence-verifiable-units/SKILL.md)**). Run the tests and inspect the actual rendered or generated output against an independently derived expectation (**[prove-it-works](../principles/prove-it-works/SKILL.md)**). Exercise an accepted input, a rejected input, and the plausible wrong result. For generators, run twice and from a partial state (**[make-operations-idempotent](../principles/make-operations-idempotent/SKILL.md)**). Log each check as evidence; a skipped or unavailable check is `unverified`. Done when every criterion is green or explicitly unverified with the reason.
8. **Independent review** for significant behavior, security or permission, data, deployment, or agent-rule changes. The reviewer gets criteria, anti-criteria, all scoped paths, and evidence pointers, not your conclusion. Done on `Decision: PASS` or an explicit user waiver.

**Reply.** Changed files, criteria and anti-criteria status, checks actually run, review verdict, and what remains unproven at runtime. Rollout goes to Deploy with this artifact's revision.
