# Implement

The deliverable is a local, verified change to code (application code, tests, scripts, config, or infrastructure as code), ready to ship. Only the files the user asked about change. Redesign cleanly from first principles within the requested scope rather than bolting patches onto an awkward shape (**[redesign-from-first-principles](../principles/redesign-from-first-principles.md)**).

1. **Record the baseline.** Working tree status, pre-existing staged and unstaged edits, and the scoped files' current content. Name the files you own and preserve everything else. Done when baseline status and owned paths are recorded.
2. **Read the contract around the target.** Callers and producers, consumers, overrides, generated outputs, existing checks, and installed tool versions (**[ground-claims-in-the-environment](../principles/ground-claims-in-the-environment.md)**). Read any validator, renderer, or hook before running it; a local checkout can still call remote backends through the active identity (**[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity.md)**). Skip or flag any check that would hit a remote backend (Code playbooks run locally and offline only). Route broad discovery to a read-only lookup subagent that returns concise findings without writing unmanaged files outside the repo. Done when every check you plan to run is verified local-only and offline.
3. **Write criteria and make them red.** Binary criteria and anti-criteria, including one that catches a misleading pass (schema-valid but semantically wrong) (**[test-behavior-not-implementation](../principles/test-behavior-not-implementation.md)**). For a behavior-preserving refactor, pin a green observable baseline instead (exact test pass + rendered output) so checks stay tied to behavior rather than internals. When no cheap unit test path applies (pure docs, config, or scaffolds), use the closest executable check (validator, schema check, deterministic render, structural test) and log why. Done when the check fails on current code for the expected reason (or the refactor baseline is green and logged).
4. **Name the shape.** Base requirement: apply **[redesign-from-first-principles](../principles/redesign-from-first-principles.md)** — ask *"if we were writing this from scratch with this requirement, what would we build?"* instead of bolting onto an awkward design, and propagate the shape through types, callers, docs, and tests (delivering incrementally when large). Define core types, allowed states, inputs and overrides, resolving each decision in one place (**[model-the-domain](../principles/model-the-domain.md)**); parse and validate at system boundaries while keeping internal logic pure (**[boundary-discipline](../principles/boundary-discipline.md)**); in statically typed code, make illegal states unrepresentable and brand distinct primitives (**[type-system-discipline](../principles/type-system-discipline.md)**). For user-facing UI, CLI, library, or API surfaces, prioritize consumer clarity over implementation convenience (**[experience-first](../principles/experience-first.md)**). For infrastructure, also name environment identity, resource ownership, and stateful guards in source (`prevent_destroy`/deletion protection, retention, isolated backups, locked shared state — **[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity.md)**, **[design-recovery-first](../principles/design-recovery-first.md)**; report missing guards as findings). Retry logic retries only transient errors with backoff, jitter, and a cap, at one layer. For a novel consequential design, compare 2–3 prototypes or sketches first (Exhaust the Design Space) and let the main orchestrator run a `Mode: plan` review under `work/SKILL.md`'s significance gate before building; for a mechanical edit, follow the existing pattern. Done when the target shape and boundaries are explicit.
5. **Split into workstreams.** Map the work as a **task graph**: the workstreams the spec or plan declares, plus any found in steps 2 to 4, and which blocks which. Shared types, schemas, and scaffold land first, before any stream starts (**[foundational-thinking](../principles/foundational-thinking.md)**). With one stream — or when running inside a delegated subagent or a runtime without nested subagents — work inline sequentially (or let the main orchestrator split independent units). When two or more sit on the **frontier** (unblocked, with disjoint file scopes), run them as parallel implementer subagents in isolated worktrees/branches when available, or on the working tree with disjoint file scopes (**[separate-before-serializing-shared-state](../principles/separate-before-serializing-shared-state.md)**). A stream edits only its file scope, runs only checks scoped to those files, keeps no separate work log, and hands back its changed paths and evidence for the parent to log; the parent keeps staging, commits, the work log, shared files (lockfiles, generated outputs), generators, and whole-suite checks. Open each stream brief with the goal, include the work skill's two-case comment rule, and pass context pointers to the spec, plan, discovery notes, commits, criteria, file scope, and the stream rule above. Done when every stream has an owner and no two streams write the same file.
6. **Make the smallest correct change** to reach the clean Step 4 shape (Laziness Protocol — no bolted-on hacks and no unasked abstractions). Subtract what this change makes obsolete (**[subtract-before-you-add](../principles/subtract-before-you-add.md)**). For an owned offline rewrite where every consumer ships together, converge on the target shape without throwaway shims (**[outcome-oriented-execution](../principles/outcome-oriented-execution.md)**); otherwise keep compatibility paths whose consumers you have not inventoried (**[preserve-compatible-transitions](../principles/preserve-compatible-transitions.md)**). Keep only comments that satisfy the work skill's two-case rule. For a refactor, require test results unchanged and rendered output byte-identical afterwards.
7. **Verify offline in units.** With parallel streams, accept each finished stream in turn: verify its diff strictly inside its scoped paths (`git diff -- <scoped paths>`), revert or re-scope any out-of-scope edit or failed stream before continuing, log its evidence, and dispatch what it unblocked; once no stream is in flight on the frontier, audit whole-tree `git status` minus the Step 1 baseline and run generators and whole-suite checks (**[sequence-verifiable-units](../principles/sequence-verifiable-units.md)**). Run the tests and inspect the actual rendered or generated output against an independently derived expectation (**[prove-it-works](../principles/prove-it-works.md)**). Exercise an accepted input, a rejected input, and the plausible wrong result. For generators, run twice and from a partial state (**[make-operations-idempotent](../principles/make-operations-idempotent.md)**). Log each check as evidence; a skipped or unavailable check is `unverified`. Done when every criterion is green or explicitly unverified with the reason.

**Reply.** Changed files, criteria and anti-criteria status, checks actually run, and what remains unproven at runtime (the main orchestrator applies `work/SKILL.md`'s significance gate for independent review). Rollout goes to Deploy with this artifact's revision.
