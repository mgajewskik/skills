# Incident

For active consumer impact. The deliverable is impact reduced through a containment, verified at the consumer, with cause confidence tracked separately. Contain active impact first, then diagnose cause; treat containment as recovery, never as root cause. Urgency shortens prose, never the authority rule.

1. **Establish impact and command.** Who is affected and how, since when, the incident owner, the permitted response, and the channel. Start the work log now; every action and observation gets an entry. Done when impact is a sentence with a number or scope in it.
2. **Preserve the smallest evidence.** Before containment changes the system, capture the bounded signals that would otherwise be lost (the failing request, the current revision and config, the relevant window of errors) (**[leave-no-residue](../principles/leave-no-residue.md)**), saved as artifacts. No unrestricted log or secret dumps. Done when volatile evidence is saved as bounded artifacts.
3. **Offer containment.** One to three bounded options (shift traffic, roll back to the last accepted revision, disable a feature, shed load, restart), each with expected effect, risk, reversibility class (per `work/SKILL.md`), recovery (**[design-recovery-first](../principles/design-recovery-first.md)**), and the signal that shows it worked. Log each option as a note. Done when bounded containment options with recovery limits are logged and ranked.
4. **Contain** (**[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity.md)**). Outside production, a reversible option may be logged as `plan --by agent` with its revert, executed after stating which and why in one line, and logged with `run --from-plan <n> --outcome ok|failed|unknown --result ...`. In production the user chooses, and the containment is handed over as `plan --by user`, unless a session grant covers it and it is reversible. A restart that drops in-flight work or state is irreversible (`--by user`). Done when the chosen containment is executed and logged, or handed over as a logged user plan.
5. **Verify containment at the consumer** (**[prove-it-works](../principles/prove-it-works.md)**). For a handed-over containment, first confirm the user ran the exact command and log `run --from-plan <n> --by user --outcome ok|failed|unknown --result ...`. Log residual consumer impact as evidence. Improvement after a restart or rollback establishes recovery, not cause. If containment fails to reduce impact or worsens it, revert an agent-executed containment from `revert-plan` (logged with `--reverts <n> --outcome ok|failed|unknown`) or hand the revert over, then evaluate the next option from step 3. Done when consumer impact is reduced on evidence (or the incident owner escalates).
6. **Diagnose.** Run Debug on the preserved evidence and current state (**[fix-root-causes](../principles/fix-root-causes.md)**), then return to step 7. Keep competing hypotheses open; the incident does not need a single cause to close. Done when Debug concludes with observed facts, root-cause confidence (`established`, `leading-hypothesis`, or `unknown`), and open unknowns.
7. **Hand off durable work.** Prevention goes to Implement and Deploy; a temporary workaround gets an owner and an expiry or revisit condition, and a containment you executed stays in the log's revert list until reverted or adopted into source. At a shift change, log a resume note: what changed on which targets, what did not, the open hypotheses, and the next observation. Done when durable follow-ups and every active workaround have an owner.
8. **Close.** Timeline from the log, containment evidence, cause and its confidence logged via `root-cause`, open unknowns, the residue list with each item removed or owned (**[leave-no-residue](../principles/leave-no-residue.md)**), and each recurring lesson encoded as a check, alert, or protection rather than a sentence (Encode Lessons in Structure). Done when `root-cause` is recorded, residue is cleared or owned, and the log is closed.

**Reply.** Impact now versus at start, containment and its evidence, cause status (`established`, `leading-hypothesis`, or `unknown`), open risks, and the next action.
