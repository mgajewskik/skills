# Fix

For a defect in code: a wrong result, a crash, a failing check, or a bug traced back to source. The deliverable is the root cause fixed locally, plus a regression check that was red on the old code and is green on the new, kept so the bug cannot come back unseen. A live symptom with an unknown cause starts in Debug; a cause Debug traced to source continues here.

1. **Record the baseline.** Working tree status and pre-existing staged and unstaged edits. Name the files you own and preserve everything else. Done when you can tell your diff apart from anyone else's.
2. **State the defect.** Intended behavior, actual behavior, the affected path, and the smallest input that shows it. Write it as a binary criterion, plus an anti-criterion that catches a masked symptom (the error is swallowed, clamped, or retried away while the wrong state remains). Done when you can write the expected result as a literal.
3. **Make it red.** Find the narrowest existing test that runs this path and add the smallest test that would have caught the bug, driven through the interface the path's users call (**[test-behavior-not-implementation](../principles/test-behavior-not-implementation/SKILL.md)**). Read any validator, renderer, or hook before running it, since a local checkout can still call remote backends through the active identity. Run the test before touching the code. A pass, or a failure for another reason, means the test or the repro is wrong; fix that first. A flaky defect gets a deterministic check (fixed seed, clock, or ordering) that names the signal it locks. When no cheap test path exists (it would need a broad new harness, mocks of internals, slow end-to-end infrastructure, or a deployed system), use the closest executable check instead (a script, a deterministic render, a validator run, a log assertion), log why, and name the post-deploy check for Deploy when only a live system shows the defect. A bad test is worse than none: one that mostly exercises mocks, pins internals, depends on timing or global state, or would be deleted right after proving the fix. Done when the check is red for the reason stated in step 2 and logged as evidence.
4. **Find the root cause.** Ask why from the symptom until the answer is a wrong decision in the code, and decide whether the state that triggered it is legitimate (**[fix-root-causes](../principles/fix-root-causes/SKILL.md)**). Done when you can name the first place the system went wrong and the red check runs through it.
5. **Make the smallest fix at the root.** Keep nearby contracts. Change an existing assertion only when the expected behavior genuinely changed, and say why. Remove any guard, retry, or swallowed error that only hid this bug. Done when the diff touches only the root decision, any assertion whose expected behavior changed (with the reason logged), and the guards that hid this bug.
6. **Turn it green and sweep for siblings.** Rerun the new check, then the tests around the changed code. Search for the same fault pattern elsewhere; fix each instance behind its own red check (**[sequence-verifiable-units](../principles/sequence-verifiable-units/SKILL.md)**) or list it as a finding. Log each check as evidence. Done when the regression check is green, the nearby checks match the baseline, and every sibling is fixed or listed.
7. **Independent review** for fixes that change significant behavior, security or permissions, data, deployment, or agent rules. The reviewer gets criteria, anti-criteria, all scoped paths, and evidence pointers, not your conclusion. Done on `Decision: PASS` or an explicit user waiver.

**Reply.** Root cause, the regression check with its red result before the fix and green after (or the substitute check and why), nearby checks run, siblings fixed or listed, review verdict, and what remains unproven at runtime. Rollout goes to Deploy with this artifact's revision.
