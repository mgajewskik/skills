# Migration

For changing a contract, data format, platform, or ownership while old and new versions coexist or data persists across the change. The deliverable is a phased plan whose every intermediate state is supported and recoverable, run through Deploy, with the old path retired only on proven coverage. Data conversions and backfills are data writes: always irreversible and user-executed (`--by user`).

1. **Inventory both sides.** Readers, writers, deployed versions, stored formats, and independently deployed consumers, from runtime evidence (access logs, connection data, dependency listings), not only source search, saved as an artifact. Done when each consumer has an owner and a version.
2. **Design the phases.** Typically expand (new path added, old kept), migrate (writers and data move), contract (old path removed). For each phase name the allowed mixed states, the version you can recover to, and the one-shot effects (data conversions, notifications) that recovery cannot undo. Per **[preserve-compatible-transitions](../principles/preserve-compatible-transitions.md)**. Mark each step reversible or irreversible under `work/SKILL.md`. Done when every phase names allowed mixed states, recovery target, and reversibility class.
3. **Fix the done predicate.** A countable statement such as "zero reads on the old endpoint for the agreed window and every consumer on the new version". Log it as a note and never relax it. Done when the countable done predicate is logged as a note.
4. **Pilot one unit end to end.** One consumer, shard, or host through every phase with full verification, to falsify the plan before scaling (**[bound-change-exposure](../principles/bound-change-exposure.md)**, **[sequence-verifiable-units](../principles/sequence-verifiable-units.md)**). The pilot is the first Deploy unit of each phase: it goes through Deploy's review, predicate, execution or handoff, and gate like any other unit. Adjust the plan from what the pilot showed. Done when the pilot passes every phase's Deploy gate and any plan adjustments are logged.
5. **Run each phase through Deploy.** Follow `work/SKILL.md` authority, reversibility, and grants via Deploy's `plan` and `run --from-plan` loop (production steps outside a grant and all irreversible steps are handed over as `--by user`). Verification covers old and new consumers in the same unit. Log evidence per unit, then return to step 6 when all units complete. Done when every unit in the phase passes Deploy's `check` gate.
6. **Retire only on proof.** The contract phase needs the predicate met on current evidence. Removing the old path or data is a Teardown. Done when the step 3 predicate is `established` on fresh evidence and contract/Teardown completes.

**Reply.** Phases with their state, pilot findings, the predicate's current count, consumers not yet moved, who executed each step, and recovery limits in force for the current phase.
