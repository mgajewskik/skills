# Live modify

For a direct change to a running system outside its normal source-and-rollout path: set a value, scale, restart, grant access, flip a flag, hand-patch a resource. The deliverable is the change made through the right path (logged as a `plan --by agent` with its revert before execution and `run --from-plan` after, or handed over as `plan --by user` and closed with `run --from-plan --by user`), verification that exactly the intended change happened, and a decision about the source of truth. A live edit nobody writes back is drift waiting to revert or surprise.

1. **Find the owner of the field.** Which source (IaC, GitOps, controller, configuration management, human) declares this value, and what reconciles it? If a reconciler owns it, the edit will be undone or fought; prefer Implement plus Deploy, or have the user pause or transfer ownership first (**[verify-the-negative-space](../principles/verify-the-negative-space.md)**). Done when every writer of the field is listed.
2. **Capture the current value as the snapshot.** Read it from the authoritative reader, bound to target and time, and save it redacted as an artifact. Write the revert command that restores exactly this value, and name what it cannot restore and what it depends on; a change to access, networking, or identity can cut off the revert's own path (**[design-recovery-first](../principles/design-recovery-first.md)**). Done when the revert could run without guessing.
3. **Specify the change.** Exact target identifiers, the identity it runs as (**[act-through-the-narrowest-identity](../principles/act-through-the-narrowest-identity.md)**), exact new value, predicted consumer effect, and how long until it takes effect (reload, restart, propagation). Prefer a conditional form that applies only if the value is still what you read, when the platform offers one. Done when the exact command, target, identity, and expected effect are written down.
4. **Write verification and negative space before execution.** The consumer-level check that would stay red if the change were a no-op (**[prove-it-works](../principles/prove-it-works.md)**), the neighbours that must stay identical (**[verify-the-negative-space](../principles/verify-the-negative-space.md)**), and the reconcile interval after which you look again. Done when verification checks, negative-space set, and reconcile interval are logged as a note.
5. **Classify and execute or hand over.** Classify reversibility under `work/SKILL.md`. Reversible, and outside production or inside a session grant: log `plan --by agent` with its revert and snapshot artifact, execute exactly that command, then log `run --from-plan <n> --outcome ok|failed|unknown --result ...`. Otherwise: log the exact command as `plan --by user` (irreversible always requires `--by user`); the user executes. Done when the change is executed and logged, or handed over as a logged user plan.
6. **Verify.** For a handed-over change, first confirm the user ran the exact command handed over and log `run --from-plan <n> --by user --outcome ok|failed|unknown --result ...`. Then re-read the live value, run the consumer check, diff the negative space, and look again after one reconcile interval to catch a silent revert. Log each claim as evidence. On a failed check for a change you executed: run its revert from `revert-plan`, log it with `--reverts <n> --outcome ok|failed|unknown`, and report. Done when consumer, live-value, negative-space, and post-reconcile checks are logged as evidence (or the revert is logged).
7. **Close the loop on source.** Either an Implement run that writes the value back to the source of truth, or a drift item logged as a note with owner and revisit date. The user chooses. Done when the user's source-of-truth decision is logged.

**Reply.** Old value, new value, who executed it, owner of the field, verification and negative-space results, revert observed or not, and the source-of-truth decision.
