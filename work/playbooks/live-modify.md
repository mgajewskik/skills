# Live modify

For a direct change to a running system outside its normal source-and-rollout path: set a value, scale, restart, grant access, flip a flag, hand-patch a resource. The deliverable is the change made through the right path (logged with its revert and executed, or handed over), verification that exactly the intended change happened, and a decision about the source of truth. A live edit nobody writes back is drift waiting to revert or surprise.

1. **Find the owner of the field.** Which source (IaC, GitOps, controller, configuration management, human) declares this value, and what reconciles it? If a reconciler owns it, the edit will be undone or fought; prefer Change plus Deploy, or have the user pause or transfer ownership first (**[infra-verify-the-negative-space](../principles/infra-verify-the-negative-space/SKILL.md)**). Done when every writer of the field is listed.
2. **Capture the current value as the snapshot.** Read it from the authoritative reader, bound to target and time, and save it redacted as an artifact. Write the revert command that restores exactly this value, and name what it cannot restore and what it depends on; a change to access, networking, or identity can cut off the revert's own path (**[infra-design-recovery-first](../principles/infra-design-recovery-first/SKILL.md)**). Done when the revert could run without guessing.
3. **Specify the change.** Exact target identifiers, the identity it runs as (**[infra-act-through-the-narrowest-identity](../principles/infra-act-through-the-narrowest-identity/SKILL.md)**), exact new value, predicted consumer effect, and how long until it takes effect (reload, restart, propagation). Prefer a conditional form that applies only if the value is still what you read, when the platform offers one.
4. **Write verification and negative space before execution.** The consumer-level check that would stay red if the change were a no-op (**[prove-it-works](../principles/prove-it-works/SKILL.md)**), the neighbours that must stay identical (**[infra-verify-the-negative-space](../principles/infra-verify-the-negative-space/SKILL.md)**), and the reconcile interval after which you look again.
5. **Classify and execute or hand over.** Check reversibility. Revoking access, rotating a secret, or anything that loses state or notifies people is irreversible. Reversible, and outside production or inside a grant: log the run with its revert, execute exactly that command, and log its outcome as evidence. Otherwise: log the exact command as a plan for the user; the user executes.
6. **Verify.** Re-read the live value, run the consumer check, diff the negative space, and look again after one reconcile interval to catch a silent revert. Log each claim as evidence. A failed check on a change you executed: run its revert from `revert-plan`, log it with `--reverts`, and report.
7. **Close the loop on source.** Either a Change that writes the value back to the source of truth, or a drift item logged as a note with owner and revisit date. The user chooses.

**Reply.** Old value, new value, who executed it, owner of the field, verification and negative-space results, revert observed or not, and the source-of-truth decision.
