# Deploy

The deliverable is a rollout executed unit by unit, each unit accepted on evidence before the next. A non-production unit that passes the reversibility checklist is executed by the agent with its own journal entry. Production units outside a grant, and every irreversible step, are handoffs the user executes. The agent never retries on its own.

1. **Pin the artifact and target.** Exact artifact revision or digest, environment, target set resolved to identifiers, the identity each unit runs as (**infra-principle-act-through-the-narrowest-identity**), who executes each unit, and installed tool versions. Identify drift, partial earlier runs, and every other writer of the same fields. Done when the target set came from a read-only query, not from memory.
2. **Take the baseline.** Current consumer behavior, effective and loaded state, and the negative-space neighbours, each bound to identity, location, and time. Done when the acceptance checks would go red if the rollout did nothing.
3. **Fix the predicate before execution.** Acceptance criteria and anti-criteria at the consumer, observation window, population, and stop thresholds chosen from this workload. Write them into each unit's journal verification or handoff. Never relax them after the first unit.
4. **Preview with the closest real engine.** Produce the plan, diff, or dry run the unit will execute against, and record what it cannot see. Replacements and deletions in a preview get named one by one; any deletion routes that part through Teardown.
5. **Cut units and classify each.** Smallest representative unit first, per **infra-principle-bound-change-exposure**. For each, answer what a repeat does, what an interruption leaves behind, and what recovery restores and cannot (**infra-principle-design-recovery-first**). Then run the contract's reversibility checklist per unit: snapshot, revert command, nothing lost or sent, verification both ways. Mixed versions or persisted formats route through Migration.
6. **Get an independent verdict on the prepared rollout.** A non-author reviewer checks the artifact, preview, unit classification, journal plans, handoffs, and criteria. Done on `Decision: PASS` bound to the artifact revision and handoff fingerprints; an edit after the verdict voids it.
7. **Run one unit.** Resolve the target and identity again and compare them with step 1. Reversible, and outside production or inside a grant: capture the snapshot, `journal.py record change`, execute exactly that command, record the result. Otherwise: lint the handoff and give the user its fingerprint and the approval command from [the handoff reference](../../references/handoff.md); the user records the approval and executes.
8. **Verify the unit.** For a handed-over unit, first check the approval still matches the fingerprint. Then observe effective state, loaded state, consumer outcome (**infra-principle-prove-consumer-outcomes**), and negative space (**infra-principle-verify-the-negative-space**) with bounded read-only probes bound to the running revision (**infra-principle-bind-evidence-to-context**). Polling for convergence follows **infra-principle-bound-retries**. Record each claim with `journal.py record evidence` against that revision. Keep rollout acceptance separate from overall application health: an unrelated existing fault does not fail the rollout, and an accepted rollout does not make the application healthy.
9. **Gate.** Advance only when `journal.py check` exits 0 for every claim of the current unit. A stop signal on a unit you executed: revert it from the journal and halt. Any stop signal, drift, ownership conflict, or unexplained partial result halts expansion and goes back to the user with evidence; a timeout or partial run gets an inventory of what completed before anyone proposes a repeat (**infra-principle-reconcile-before-retrying**). Promote only the contiguous run of accepted units. Before calling the rollout done, walk the residue list (**infra-principle-leave-no-residue**).

| State | Required evidence |
| --- | --- |
| `prepared` | Artifact, preview, unit classification, journal plans or handoffs, criteria, recovery limits, review verdict. |
| `approved` | Handed-over unit: the user's approval entry for this fingerprint. Agent-run unit: a `pending` journal entry. |
| `executed` | The journal result line, or the user's execution report. Acceptance still unverified. |
| `accepted` | Every acceptance and negative-space claim `established` for the current revision. |
| `failed` / `halted` / `reverted` | A required result failed, a forbidden result occurred, or a stop condition fired; `reverted` once the journal revert is verified. |
| `unverified` | Evidence missing, stale, from another context, or not covering the claim. |

**Reply.** Artifact revision, units with their states and who executed each, journal results per claim, review verdict, and the one next action with the minimal result to send back.
